2. TTN Credentials

Device identity and root keys

DevEUI, AppKey and NwkKey can be entered as direct continuous hex, MSB comma bytes, or LSB comma bytes. Select the input format beside each field.

TTN / OTAA

DevEUI

Unique device identifier used by TTN to recognize this node. In the generated PlatformIO file it is emitted in RadioLib-compatible 0x... form.

AppKey

Application root key used during OTAA join. Treat it as a secret; in real deployments each device should have its own key. In the generated PlatformIO file it is emitted as a RadioLib-compatible comma-separated byte list, for example 0x00, ....

NwkKey

Network root key for LoRaWAN 1.1.0. It is disabled for LoRaWAN 1.0.x because that older key model does not use a separate NwkKey here. In the generated PlatformIO file it is emitted as a RadioLib-compatible comma-separated byte list, for example 0x00, ....

3. Sensor modules

Choose the sensor building blocks for this device. Each module below contains the enable switch, the relevant pins, and the calibration values that belong to this sensor.

fPort 1

Adds location data so measurements can be mapped spatially. This is important when several buoys move or when water-quality values must be linked to a place.

No calibration is usually needed. Accuracy depends on satellite visibility; HDOP in the payload indicates how trustworthy the position is.

fPort 2

Measures water temperature. Temperature is also useful context for other values, because chemical and electrical measurements can change with temperature.

Usually factory-calibrated well enough for teaching and trend observation. Compare against a known thermometer if absolute accuracy matters.

fPort 3

Measures how acidic or alkaline the water is. pH is central for biological systems, but low-cost probes require careful calibration and maintenance.

pH calibration points

These values map ADC readings to known buffer solutions. Use pH 4, pH 7 and pH 10 calibration fluids to turn raw voltage into a meaningful pH estimate.

fPort 4

Estimates dissolved solids from electrical conductivity. It is a useful low-cost indicator for changes in water composition, but it is not a precise chemical analysis.

TDS electrical assumptions

These values describe the analog conversion. They must match the board voltage and ADC range, otherwise the calculated ppm value will be systematically wrong.

fPort 5

Estimates how cloudy the water is by measuring scattered or transmitted light. This can indicate suspended particles, algae, mud, or disturbed sediment.

Turbidity calibration line

The firmware maps voltage to NTU using two reference points. In the lab, one point can be clear water and the other a known turbid reference or a teaching approximation.

How to use the generated file

1. Put the generated file into the firmware project

  1. Download the generated file.
  2. For the simplest workflow, save or rename it to platformio.ini.
  3. Copy it into LoRaWAN-HelloWorld-radiolib/.

2. Default workflow

The generated file sets the created environment as default_envs. Therefore the usual build and upload commands do not need -e.

  • Build: pio run
  • Upload/flash: pio run -t upload

3. Explicit environment workflow

You can still select the environment explicitly. This is useful for demonstrations, scripts, or when several environments exist in one file.

  • Build: pio run -e <environment-name>
  • Upload/flash: pio run -e <environment-name> -t upload

4. Custom filename workflow

When the file has a non-default name, pass it explicitly with -c. You may combine -c with the default environment or with an explicit -e.

  • Build default environment from a custom file: pio run -c platformio.my-device.ini
  • Upload default environment from a custom file: pio run -c platformio.my-device.ini -t upload
  • Build explicit environment from a custom file: pio run -c platformio.my-device.ini -e <environment-name>
  • Upload explicit environment from a custom file: pio run -c platformio.my-device.ini -e <environment-name> -t upload

5. Monitor and TTN setup

  • Open the serial monitor with pio device monitor.
  • Generate the TTN payload formatter in the dedicated card above, then paste it into the application/device uplink payload formatter in The Things Stack.

LoRaWAN notes

LoRaWAN 1.1.0 uses separate network and application root keys. In this firmware that means AppKey and NwkKey are both configured.

LoRaWAN 1.0.x uses the older OTAA key model. In this firmware the generated INI omits RADIOLIB_LORAWAN_NWK_KEY, so the C++ code passes nullptr for the network key.

DevEUI identifies the device and is generated as 0x... in the final PlatformIO build flag. JoinEUI is set to zero for the TTN sandbox setup used in this course. AppKey/NwkKey are secrets and must be unique per real device.
